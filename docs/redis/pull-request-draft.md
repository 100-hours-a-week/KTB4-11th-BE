# PR 설명 초안

제목: 여러 BE의 키움 시세·조회 데이터를 Redis로 공유

아래는 저장소 PR 양식에 맞춘 본문 초안이다. 실제 PR 생성·원격 게시·배포 기록이 아니다. 연관 이슈와 병합 대상은 게시 전에 확인한다.

## 작업 요약

BE를 여러 대 실행할 때 각 서버가 키움 시세를 중복 수집하고 메모리 데이터를 따로 보관하는 문제를 해결한다. 고정 담당 BE 한 대가 키움 REST·WebSocket을 처리하고 최신 시세·호가·종목정보·지수·토큰을 Valkey에 저장하며, 일반 BE는 내부 인증 REST와 종목별 Pub/Sub로 공유한다.

## 작업 세부 내용

- 담당 활동과 접수 중 구독 수요를 `coord:*`로 공유하고 DB 대기 주문에서 구독을 복구한다. 담당 자동 인계는 하지 않는다.
- 개별 TR의 최근 1초 최대 5회까지 즉시 호출하고 초과 요청은 최대 3초 기다린다. 만료 요청은 외부 호출 전에 실패하며 내부 API는 503을 반환한다.
- 담당·종목 구독·연결 ID를 검증하여 이전 연결 시세를 주문에 사용하지 않는다. Redis/담당 장애 시 신규 주문·체결을 중단하고 대기 주문을 유지한다.
- 가격 조건 미충족 주문의 반복 잠금을 생략하고 목록·보고서를 함께 조회하여 반복 SQL을 제거한다. 실제 체결의 계좌 잠금·상태·가격·출처 재검증은 유지한다.
- TTL·ACL 요구 사항, 환경변수 예시와 배포·복구 절차를 `docs/redis`에 정리한다. 인프라 ACL의 `coord:*` 추가와 역할별 서비스 설정이 필요하다.

검증: 로컬 Valkey·ACL·다중 JVM·장애 복구·REST/주문 부하 포함 전체 282개 중 276개 통과, 실제 키움 연결 테스트 6개 건너뜀, 실패·오류 0건. 최신 주문 부하에서는 알림 40개를 일반 BE 두 대가 각각 수신했고 주문 100개가 각각 한 번 체결됐다. 체결 단계 약 3.5초는 로컬 가짜 키움/H2 수치다. 실제 MySQL·배포 Valkey ACL/TLS·키움과 BE 세 개의 결합 검증은 접속 설정 확보 후 수행한다.
