# 체결 서버 분리 철회 (2026-10-14)

체결은 기존 `RiverBeApplication` 안에서 실행한다. 주문과 체결 패키지 구분 및 기존 Redis 적용은 유지한다.

- 주문 컨트롤러가 같은 프로세스의 체결 서비스를 직접 호출한다.
- 별도 ExecutionApplication, 실행 프로필, 내부 HTTP API와 인증, 전용 JAR 및 Dockerfile을 제거한다.
- CI는 일반 BE 빌드만 실행하며 기존 이미지 배포 작업은 유지한다.
- `EXECUTION_SERVER_URL`, `EXECUTION_INTERNAL_SECRET`은 더 이상 사용하지 않는다. 별도 체결 프로세스를 운영 중이라면 일반 BE 전환 시 중지해야 한다.
- 내부 요청 중복 방지용 `execution_requests` 엔티티와 생성 SQL을 제거한다. 실제 DB에 테이블이 이미 존재하는지는 확인하지 않았으며, 데이터 삭제나 DROP은 수행하지 않았다. 새 테이블 생성은 필요 없다.
- 기존 계좌 DB 락과 주문 상태 확인은 유지한다. 별도 내부 요청 번호 기반 결과 조회는 제거된다.
- Redis 시세 조회·Pub/Sub, 기존 수집 담당 기능과 구독 수요 관리는 유지한다. AI 시세 서버 규격 연동 및 기존 수집 기능 제거는 별도 작업이다.

배포 담당자는 기존 별도 체결 서버의 실행 여부와 관련 환경변수를 확인한다. 이 변경은 애플리케이션 코드의 복구이며 배포 환경을 직접 변경하지 않는다.
