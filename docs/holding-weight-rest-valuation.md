# 매수 체결 후 비중의 REST 평가

## 원인
웹소켓 구독은 접수 중이거나 PENDING 주문이 있는 종목만 유지한다.
기존 비중 계산은 다른 보유 종목의 웹소켓 현재가를 요구하여 정상적으로 구독이 종료된 종목도 비중을 null로 만들었다.

## 처리
1. 시장가 매수는 OrderController, 지정가 매수는 OrderExecutionListener에서 OrderBuyPriceService.fetch를 호출한다.
2. 이번 매수 종목을 제외한 보유 종목의 현재가를 기존 KiwoomMarketClient.currentPrice로 REST 조회한다.
3. 가격 조회는 체결 트랜잭션과 계좌 잠금 전에 수행한다. 시장가 호가는 REST 조회 후 읽는다.
4. OrderExecutionService는 계좌 잠금 아래 현금과 보유 수량을 반영한 뒤 확보한 가격으로 평가한다.
5. 매수 종목은 이번 평균 체결가 × 체결 후 전체 보유 수량, 다른 종목은 REST 가격 × 체결 후 보유 수량으로 평가한다.
6. 비중 = 매수 종목 평가액 / (체결 후 현금 + 전체 보유 평가액) × 100. 소수4자리 반올림 후 리포트에 저장한다.

REST 조회 실패/0 이하 가격 또는 가격 확보 후 추가된 보유 종목의 가격 누락 시 비중만 null로 남기고 체결은 유지한다.
로그 order_buy_weight_price_failed는 REST 조회 실패, order_buy_weight_unavailable는 체결 후 필요한 가격 누락을 뜻한다.
매도에는 평가용 REST 조회를 추가하지 않는다. 기존 null 리포트는 다시 계산하지 않는다. DB 스키마 및 응답 필드는 변경하지 않는다.
REST 조회 시점은 종목마다 다르고 체결 시점과 약간 차이가 있다. 지정가 시세 처리는 기존 동기 흐름이므로 REST 조회 중 처리가 지연될 수 있다.

## 검증
시장가/지정가 모두 다른 보유 종목의 웹소켓 가격 없이 REST 가격으로 비중을 저장하는 회귀 테스트를 추가했다.
REST 실패에도 전량 체결되고 비중만 null로 남는 경우, 추가매수 후 전체 수량 사용, 저장된 비중 유지, REST 조회 대상과 양수 검증을 확인한다.
