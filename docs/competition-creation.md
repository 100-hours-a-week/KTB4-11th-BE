# 대결 생성

`POST /api/v2/users/me/competitions`는 일반 사용자 Access Token과 기존 CSRF 정책을 사용한다.
요청 DTO는 `@Valid`로 검사하고 서비스는 사용자·업무 규칙을 확인한다.

- 온보딩 완료 사용자만 생성할 수 있다. 일반 계좌 생성과 같은 조건이다.
- `competition_type`은 `user_vs_ai`, `ai_participant_count`는 1이다.
- 시작일은 한국 시간 기준 생성 당일이고 종료일과의 날짜 차이는 최소 3일이다.
- 대결명은 공백을 제거한 20자 이하이며 같은 사용자의 계좌명과 중복될 수 없다.
- 사용자 계좌명은 대결명, AI 계좌명은 내부 이름 `AI-{대결ID의 36진수}`다. 내부 이름 충돌 시 접미사를 붙인다.
- 두 계좌는 각각 동일한 초기 자금을 받으며, 참가자 테이블로 대결과 연결한다.
- 대결·두 계좌·참가자 저장을 한 트랜잭션으로 처리한다.

## 시작과 대기

한국 시간 평일 09:00 이상 15:30 미만이면 생성 시 `in_progress`, 그 외에는 `ready`다.
`CompetitionStartScheduler`는 기본 10초 간격으로 장이 열렸는지 확인하고 기간 내 대기 대결을 시작한다.
요청받은 종료일은 연장하지 않으며 실제 시작 시각은 `started_at`에 기록한다.
현재 공휴일·연휴는 고려하지 않는다. 종료일은 해당 날짜를 포함한다.

`competition.start.enabled=false`로 자동 시작 처리를 끌 수 있다.
`competition.start.interval-ms`로 확인 간격을 변경할 수 있다.
자동 시작은 DB 잠금으로 중복 실행을 방지한다.

## 기존 기능 연결

계좌 목록은 대결 AI 계좌만 제외한다. 사용자 대결 계좌에는 `is_duel_account=true`를 반환한다.
AI 서버 계좌 조회에는 기간 내 진행 중 대결의 AI 계좌만 포함한다.
대기·취소·완료 상태 또는 기간 밖의 대결 계좌는 기존 AI 주문 생성·체결 경로에서도 거절한다.
일반 계좌 생성과 이름 변경도 사용자 잠금을 공유해 대결 생성과의 이름 경쟁을 방지한다.

기존 v1 일반 AI 계좌의 운용 방식과 저장 데이터는 이번 생성 API 작업에서 전환하지 않는다.
v2 일반 계좌를 사용자 운용으로 전환하고 사용자 직접 주문을 지원하는 작업은 별도 필요하다.
일별 수익률 기록·결과 상세 API·리포트 조회는 후속 기능이다.

## 대결 목록 조회

`GET /api/v2/users/me/competitions`는 로그인 사용자의 모든 대결을 생성일 내림차순,
같은 생성일이면 ID 내림차순으로 반환한다. 페이지네이션은 적용하지 않는다.
FE는 `competitions` 배열로 상단 최대 3개 카드와 하단 필터 목록을 구성한다.

- `ongoing_competition_count`는 `in_progress` 개수다. `ready`는 포함하지 않는다.
- `d_day`는 한국 날짜 기준 종료일까지의 일수이며 최소 0, 완료·취소 시 null이다. DB에 저장하지 않는다.
- `ready` 수익률은 0이다. 종료 시각 전 `in_progress` 수익률은 사용자 계좌의 현금과 보유 주식 현재 평가액으로 계산한다.
- AI 계좌 수익률과 보유 종목 수는 반환하지 않는다.
- 완료 대결은 저장된 사용자 최종 수익률과 `winner`(`user` / `ai` / `draw`)를 반환한다.
- 미확정 승자는 null이며 취소·종료 후 정산 대기 대결의 수익률도 null이다.
- 대결이 없으면 개수 0과 빈 배열을 반환한다. 시세 장애는 기존 계좌 평가와 동일하게 오류를 반환한다.

## 종료 정산

평일 종료일은 해당일 한국 시간 15:30, 주말 종료일은 직전 금요일 15:30을 거래 종료 시각으로 삼는다.
공휴일은 아직 반영하지 않는다. 요청받은 종료일 자체는 변경하지 않는다.
주문 생성·체결은 이 시각부터 차단하므로 정산 스케줄러가 늦어져도 거래할 수 없다.

`CompetitionCompletionScheduler`는 기본 1시간마다 미완료 대결을 찾고, 대결별 서비스 트랜잭션을 호출한다.
과거 미처리 대결도 찾아 서버 재시작 후 재시도한다. 대결과 계좌를 잠근 뒤,
종료 거래일의 원주가 종가(키움 ka10081, 수정주가 미적용)로 보유 주식을 평가한다.
최종 자산·수익률, 승자, 완료 처리 시각, 대기 주문 취소와 `completed` 변경을 함께 저장한다.
승자는 반올림 전 자산/초기자금 비율로 비교한다. 보유 주식을 강제 매도하거나 현금을 변경하지 않는다.

종가가 없거나 조회가 실패하면 해당 대결의 정산은 롤백하고 다음 주기에 재시도한다.
완료된 대결은 재정산하지 않으며 현재가로 최종 결과를 대체하지 않는다.
`competition.completion.enabled=false`로 끄거나 `competition.completion.interval-ms`로 주기를 바꿀 수 있다.
`ready` 상태에서 서버 장애로 시작 자체를 못한 대결의 만료 정책은 후속 작업이다.

## DB 적용

기존 `users`, `accounts`가 준비된 환경에 `db/competition.sql`을 적용한다.
기존 대결 테이블이 이미 있으면 대신 `db/competition-completion.sql`로 정산 컬럼만 추가한다.
운영 DB에 SQL을 자동 실행하거나 데이터를 변경하지 않았다.
개발/운영 스키마가 이미 존재하면 해당 스키마에 맞춘 변경 SQL을 별도로 확인해야 한다.
