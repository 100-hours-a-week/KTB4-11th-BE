# 배포 IAM·클러스터 연결 보완

사용자가 승인한 기준: 인프라 변수 이름을 유지하고 `ELASTICACHE_CACHE_NAME`이 있으면 Serverless IAM 인증, 없으면 기존 로컬/비밀번호 연결을 사용한다. `REDIS_CLUSTER_MODE`로 클러스터 연결을 선택하고 `REDIS_SSL`로 TLS를 제어한다. 새로운 인증 모드 변수는 추가하지 않는다.

1. AWS SDK v2 서명·자격 제공 기능으로 Serverless `connect` SigV4 토큰을 생성한다. AWS 기본 자격 체인으로 인스턴스 역할을 사용하며 비밀값은 출력하지 않는다.
2. Lettuce credentials provider로 새 연결·재연결에 토큰을 제공한다. 10분마다 새 자격을 발행하고 Lettuce 재인증 기능으로 장시간 연결을 갱신한다. 갱신 실패 로그는 예외 종류만 남기고 다음 주기에 재시도한다.
3. Spring Redis 연결 구성을 로컬/클러스터로 분기한다. 기존 3초 제한과 TLS 인증서 검증을 유지한다. IAM에 필요한 사용자명·리전·TLS·클러스터 설정이 없으면 기동을 거절한다.
4. 가짜 AWS 자격으로 서명 내용·시간 변화·스트리밍 갱신을 검증하고, 실제 Redis 접속 없이 역할별 연결 구성을 검증한다. 기존 로컬 Valkey·주문 전체 회귀와 빌드/정적 분석을 실행한다.
5. 전달받은 환경변수 예시와 인프라 인계 문서를 IAM 기준으로 갱신한다. 실제 IAM 인스턴스 연결은 로컬 시험과 구분하며 검증 완료로 표시하지 않는다.

연결·인증 외의 Redis 저장 키·TTL·담당 정책·주문 체결 정책은 유지한다. 실제 인프라 IAM 권한이나 사용자 ACL은 변경하지 않는다.

구현 및 로컬 검증 완료: 전체 290개 중 284개 통과, 실제 키움 연결 6개 건너뜀, 실패·오류 0건. 실행 JAR·SpotBugs도 통과했다. 상세 기록과 실제 인프라 확인 범위는 [IAM 연결](iam-connection.md)을 참고한다.
