# 지정가 예약 주문

2026-10-22 복구 브랜치 기준. 주문 생성은 기존 계좌 API에서 AI/USER를 구분한다. 별도 예약 API나 DB 테이블은 추가하지 않는다. 배포 여부는 별도 확인한다.

## 동작

- 지정가 주문은 장전·장후·야간·주말에도 접수한다. 시장가는 한국 시간 평일 09:00 이상 15:30 미만에만 전량 체결하며, 장외·주말은 `409 ORDER_WINDOW_CLOSED`로 거부하고 주문을 저장하지 않는다.
- 인증, 계좌 소유권·활성·주문 주체와 운용 유형 일치 및 대결 제한, 지정가 호가 단위, 가용 현금·매도 가능 수량 검증은 유지한다. 현재 주문 생성 경로는 외부 종목정보를 조회하지 않는다.
- 주문은 MySQL에 `PENDING`으로 저장한다. 매수 금액과 매도 수량은 기존 대기 주문 기반 계산으로 예약하며, 실제 잔액과 보유 수량은 체결 때 변경한다.
- Redis/실시간 구독 연결이 실패해도 저장된 지정가 예약은 유지한다. 구독은 시작 시와 5초 주기에 DB 대기 주문을 읽어 복구한다. 시장가 처리 중에는 임시 요청 수요도 합쳐 구독을 유지하며, 시장가는 호가 확보 실패 시 저장하지 않는다.
- 거래일이 바뀌거나 15:30이 되어도 자동 취소하지 않는다. 사용자가 취소하거나 체결될 때까지 유지한다. 사용자 취소 시 예약 현금·수량이 해제된다.
- 체결은 한국 시간 평일 09:00 이상 15:30 미만에만 진행한다. 계좌 DB 락을 잡은 뒤와 자산 변경 직전에 시간을 확인한다.
- 장외/이전 거래일 주문은 새 실시간 가격 이벤트를 기다린다. 개장·재연결 자체가 체결을 발생시키지 않는다. Redis 구독 ACK에서 저장 시세를 재발행하지 않는다.
- 새 시세의 수신 날짜와 체결 시각이 당일 장중인지, 미래 시각은 아닌지, 수집 연결·출처가 유효한지 확인한다. 기존 현재가에 별도 초 단위 만료 기준은 추가하지 않는다.
- 장중 신규 지정가 주문의 최초 판단은 유효한 당일 장중 Redis 가격이 있으면 사용한다. 없으면 새 이벤트를 기다린다. 시장가는 최신 호가를 최대 3초 대기하고, 확보하면 신선도·출처·자산을 검증해 체결한다. 체결용 REST 가격 보충은 없고, AI 보고서의 다른 보유 종목 평가도 기존 Redis 조회를 사용한다.
- 여러 BE의 동시 판단은 기존 계좌 락과 `PENDING` 상태 재확인으로 보호한다. 주문 선착순은 보장하지 않는다.

## 예시

금요일 밤 삼성전자 지정가 매수 → 현금 예약과 함께 대기 → 주말 동안 유지 → 월요일 장중 새 시세 수신 → 지정가 조건을 만족하면 한 번 체결. 월요일 새 시세가 없으면 계속 대기한다. 이전 금요일 가격은 월요일 체결에 사용하지 않는다.

## 운영 범위

공휴일·임시 휴장일 달력 연동은 사용자 결정으로 별도 작업이다. 이번에는 주말·시간 제한과 신뢰하는 수집 서버의 당일 장중 실시간 체결 시세를 기준으로 판단한다. 현행 시세 형식은 거래 시각(LocalTime)과 수신 시각(Instant)을 사용하며 거래소의 별도 거래일 필드는 없다. 수집 서버는 과거 가격을 현재 실시간 이벤트로 다시 발행해서는 안 된다.

체결 서버 분리와 AI 시세 서버의 Redis 규격 연동은 이번 변경 범위에 포함하지 않는다. DB 스키마·환경변수 추가는 없다.

## 검증

API 장외/주말 접수와 Redis 장애, 시장가 거절, 예약 자산과 취소, 금요일·주말 주문의 월요일 이벤트 체결, 이전 시세 무시, 중복 이벤트, 09:00/15:30 경계, 검증 중 마감 도달, 기존 대회 제한을 자동 테스트한다. 실제 거래소 장중/휴장일 운영 검증은 별도다.

실행 결과: `gradlew.bat build --build-cache` 성공(SpotBugs 포함), 전체 313개 중 292개 통과·21개 외부 환경 테스트 건너뜀·실패 0개. 이후 `REDIS_LIVE_TEST=true`로 `OrderExecutionEventTests`를 실행하여 로컬 Valkey(6380)의 실제 Pub/Sub·동시 구독을 포함한 5개 테스트 모두 통과했다. DB 검증은 H2 기반이며 배포 MySQL/Valkey 및 실제 키움 시세 검증은 수행하지 않았다.

위 결과는 2026-10-16 지정가 예약 구현 당시 기록이다. 2026-10-22 시장가 복구의 새 검증 결과와 범위는 [복구 계획 실행 기록](superpowers/plans/2026-10-22-restore-market-orders.md#실행-기록)에 기록한다. API 입력·호가 규칙·오류는 [현재 주문 생성 API](stockspoon_order_create.md)를 기준으로 한다.
